# Webクライアント仕様書

FieldLinker Display の動作確認用に実装した Web クライアントの仕様をまとめる。

## 1. 目的
- Raspberry Pi サービス (FastAPI) の WebSocket エンドポイント `ws://<pi-host>:8000/ws/frame` に対し、ブラウザのみでフレーム送信テストを行う。
- 単色・ランダムパターンを生成し、任意の `frame_id` を付与して送信できる。
- 接続状態、ACK/エラー応答、自動送信の ON/OFF を画面上で即時確認する。

## 2. システム構成
- 静的ファイル (HTML/CSS/ES Modules) のみで構成。
- 任意の HTTP サーバー (`python -m http.server` など) 経由でブラウザから開く。
- 依存ライブラリはゼロ (純粋なブラウザ標準 API)。

## 3. UI/機能概要
| 区画 | 機能 |
| --- | --- |
| 接続設定 | WebSocket ホスト (IP or hostname) / frame_id / 自動送信間隔(ms) の入力欄と、接続・切断ボタン。接続状態を表示。 |
| フレーム生成 | 単色 (RGB 指定)・ランダム生成・リセットの各ボタンで `pending frame` を上書きし、1回送信/自動送信ボタンで FPGA へ送出。ブラシ色は数値入力に加え、Hue/S/V のグラデーションバーで直感的に設定可能。 |
| プレビュー | `panel/neopixel_map.csv` を JSON にした `assets/pixel_map.json` を読み込み、Canvas 上で LED 配置（螺旋マップ）を描画。最新の送信内容を色として反映し、Canvas 上でドラッグすると個別の LED 色を上書きできる。 |
| ログ | WebSocket メッセージとクライアント側イベントを時系列で表示。クリアボタンあり。 |

## 4. WebSocket プロトコル
- 送信メッセージ:  
  ```json
  {
    "frame_id": <int>,
    "data": "<Base64 エンコード済み 3600 バイト>"
  }
  ```
- `frame_id` は UI の入力値から自動インクリメント。Base64 は `Uint8Array`→`btoa`。
- 受信メッセージ: サーバーからの ACK (`{"status":"ok","frame_id":...}`) またはエラー (`{"status":"error","reason":"..."}`) をそのままログ表示。

## 5. フレーム生成・可視化仕様
- 単色生成: RGB 各 0–32 の値を `LEDS=1200` 個分すべてに適用 (低輝度でも十分可視なため)。
- ランダム生成: `crypto.getRandomValues()` をベースに 0–32 へスケーリングした 3,600 バイトを生成。
- プレビュー: `assets/pixel_map.json` の `x/y` を正規化し、Canvas 上で各 LED を半径 2.5px の円として表示。送信した `Uint8Array` から色を取得し即時描画。
- プレビューキャンバス上でポインタをドラッグすると、その座標に最も近い LED を「ブラシ色」(0–32 の RGB) で塗りつぶし、次回送信するペイロードに反映させる。
- ブラシ色は RGB 数値入力に加え、Hue/Saturation/Value それぞれのグラデーションバーをドラッグして直感的に選択でき、選択結果は 0–32 の範囲に自動変換される。

## 6. 自動送信
- 入力したミリ秒間隔で `setInterval` を使って `sendFrameOnce()` を呼び出し、停止時は `clearInterval`。
- WebSocket が切断された際は自動的に停止。

## 7. 想定利用フロー
1. `python -m http.server 8080` などで `webclient/` を配信。
2. ブラウザで `http://localhost:8080` を開く。
3. WebSocket URL に Pi のアドレス (例: `ws://192.168.0.20:8000/ws/frame`) を入力し接続。
4. 単色生成 or ランダム生成でベースを作り、必要ならブラシで書き込み → 「1回送信」または「自動送信開始」。
5. `/healthz` と同様、ログ欄や LED 表示で反応を確認。

## 8. 注意点・重要ポイント
- URL バリデーションは簡易チェックのみ。HTTPS 越しに使う場合は TLS 終端 (wss://) を別途用意する。
- Base64 生成の際に `FRAME_SIZE (3,600)` を変えた場合はサーバー側設定と一致させること。
- 自動送信間隔は MCU/FPGA の処理能力を超えないよう、必要に応じて 100–200ms 以上に設定する。
- エラー発生時はログ欄に理由を表示し、ユーザーに再送を促す。
